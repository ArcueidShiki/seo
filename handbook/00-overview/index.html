总览

这是一本给独立开发者和小团队用的 SEO / GEO 实战手册。内容整理自公开的飞书知识库「独立开发前线｜SEO从0到100」的 91 篇文档：按主题重新编排，用自己的话转述，标出各篇文档之间互相矛盾的地方，并补上到 2026 年为止已经变化的做法（用 ⚠️ 2026 更新 标注）。

1. 这本手册是什么，怎么和工具配合使用

本仓库由三部分组成，分工如下：

组成 位置 回答的问题
📘 知识手册（本手册） handbook/*.md → 站点 /handbook/ 为什么要这样做、怎么做、数字门槛是多少、哪些做法已经过时
✅ 交互式 Checklist 工具 /tool/ 要检查什么：每一条都有类别、阶段、优先级、检查标准和工具。可以按阶段、优先级、自动 / 人工筛选，勾选状态保存在本地，支持导出 Markdown
🤖 auditor 审计脚本 auditor/audit.mjs 现在做到了几分：爬取你的网站，自动判定 39 条可检测的条目，并跑 Lighthouse（移动端 + 桌面端）。结果可以叠加显示在 Checklist 工具里

推荐用法

  1. 先看本章第 3 节的路线图，确定你现在处在哪个阶段。

  2. 打开 Checklist 工具，按"阶段"筛选出当前要做的条目。

  3. 用 auditor 给自己的网站打分：

    node auditor/audit.mjs --url https://your-site.com/ --name mysite --keyword "your main keyword"
# 可选参数：--max-pages 30  --no-lighthouse
# 输出到 reports/mysite.json，重新构建之后就能在 Checklist 工具里叠加查看

  4. 遇到没通过的条目，用它的 id（手册里用反引号标注，例如 tech-canonical、geo-answer-first）在对应章节里搜索，就能找到原因和修复方法。

  5. 关键词研究、外链、发布、平台运营、变现这类没法自动检测的条目，按手册的做法完成后在工具里人工勾选。

  6. 每个月重新跑一次 auditor，再对照路线图里的指标做一次复盘。

手册里的符号

  • onpage-title 这种反引号里的 id，是 Checklist / auditor 的条目编号。
  • ⚠️ 2026 更新：原文的建议已经过时、和其他文档冲突，或者存在争议。
  • 文中的 DR、价格、流量等数字都是原文撰写时的快照，使用前请自己核实。
  • 每章末尾的"来源"列出了用到的原文档，可以点进飞书看原文。

3. 新站 0→12 个月路线图

4. 30 条最重要的原则

  1. 先有搜索需求，再有页面：每个页面都要对应一个真实的查询（工具数据或搜索框联想词）。
  2. 一页一词：一个主关键词只对应一个 URL，用规划表防止多页争同一个词。
  3. 新站从 KD < 20、月搜索量 > 500 的词起步，有了外链基础再挑战 KD 30–50。
  4. 页面类型跟着 SERP 走：Top 10 是教程就写文章，是工具页就做工具页。
  5. 做不到第一就继续缩小范围：流量向第一名集中，第二名以后能分到的很少。
  6. 选词先看 7 / 30 / 90 天和 5 年的趋势：选平稳或上升的词，不追一次性的尖峰。
  7. 核心价值不设门槛：主要功能免登录就能用，内容不锁在注册或付费墙后面。
  8. 每个页面的 title 都不一样（主关键词靠前，中文 ≤ 30 字 / 英文 ≤ 60 字符），description 也每页单独写。
  9. 每个页面只有一个 H1，用大白话写清楚"它能做什么"，不用"赋能""重新定义"这类词。
  10. 每个可索引页面有一个自引用的绝对 canonical；www / 裸域、http / https 一跳 301 合一。
  11. 正文必须在 HTML 源码里（SSR/SSG），Googlebot 和 AI 爬虫都依赖它。
  12. sitemap 只放希望被收录、返回 200 的规范 URL，lastmod 写真实日期；robots.txt 要声明 Sitemap。
  13. 上线当天就验证 GSC 和 Bing 并提交 sitemap，新站每周看一次索引报告。
  14. Core Web Vitals 要达标：LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1。
  15. Cloudflare 分层配置：营销页 HTML 走边缘缓存；API、认证接口、回调不缓存；花钱的接口加限流。
  16. 结构化数据只标记页面上能看到的真实信息，绝不伪造评分和评论。
  17. 博客放在子目录 /blog；首页链到重要子页面，分类页链到所有子页面，不留孤儿页。
  18. 站在用户的角度写内容：写用户最关心的 10 个问题，不写你的技术架构。
  19. 每篇支柱文章至少有一个第一手证据：截图、数字、踩过的坑、"不适合谁"。
  20. AI 可以起草，但不能直接发布原稿；规模化灌水会导致整站被降权。
  21. 用"5 篇文章法"集中火力，推一个已经排在 11–30 名的长尾词。
  22. 每月根据 GSC 查询词更新内容、改写点击率低的标题；只有内容真的改了才更新日期。
  23. 外链是信任票，不是权重果汁：来源多样比数量重要，RD 比 DR 重要。
  24. 对独立开发者来说，DR 20–40 已经够用了；真正的 KPI 是排名、自然流量和转化。
  25. 评估一条外链，要把四个要素一起看：DR、相关性、真实流量、dofollow。
  26. 外部锚文本以品牌词和 URL 为主，精确匹配的关键词锚文本只占少数。
  27. 每次发布（上线、大版本、新功能）都是一次新的提及机会；先做低成本渠道，再考虑付费渠道。
  28. 答案先行：H1 下面第一段用 ≤ 80 个词直接给出结论，每个小节都能单独被引用。
  29. 放行 AI 搜索爬虫，确保被 Bing 收录，每月用固定 prompt 测一次自己有没有被 AI 引用。
  30. SEO 要按季度来算：大约 3 个月起量，期间用社交渠道拿早期流量，用留存数据验证产品。

5. 过时做法 vs 2026 做法

主题 过时做法（原文里出现过，或者行业常见的老说法） 2026 做法 详见
关键词密度 密度保持在 2%–8%；description 里关键词出现约 3 次 关键词在 title、H1、首段、description 里各自然出现一次，用同义词和相关实体覆盖主题 02、04
meta keywords 每页必须写 3–5 个 Google 忽略，Bing 大幅降权；只在面向百度时可写可不写 02
FAQ / HowTo 富结果 加 FAQ schema 抢占 SERP 上的折叠问答位；加 HowTo 标记 2023 年起 FAQ 富结果只给权威的政府和健康网站，HowTo 已经停止展示；FAQ 内容保留下来，用于语义理解和 AI 引用 02、06
AI 内容 用"去 AI 味"工具把 GPTZero 分数压到 40% 以下就发 Google 看质量不看来源；加入第一手信息，人工审核；避开"规模化内容滥用" 04
DR 迷信 把 DR 当 KPI，追求 DR 快速上涨 看引用域名的多样性、相关性和真实流量；KPI 是排名、流量和转化 05
购买外链 批量外链包、PBN、按 DR 定价的客座文章 付费只买"审核收录 + 曝光 + 归类"（目录本身要有真实用户）；买卖传递 PageRank 的链接违反政策 05
只做 Google 只盯着蓝色链接的排名 同时做 GEO：放行 AI 爬虫、确保 Bing 收录、答案先行、站外讨论、每月 prompt 测试 06
只做百度 中文 SEO = 百度 SEO 全渠道 SEO：小红书、抖音、知乎、B 站、微信搜一搜都是搜索入口；百度上主攻品牌词 01、09、10
屏蔽 AI 爬虫 在 Cloudflare 里一键屏蔽所有 AI bot 营销内容对 AI 搜索和训练爬虫放行，只对 API 和应用路径做限流 03、06
交互指标 FID 2024 年 3 月起改为 INP（≤ 200ms） 03
GSC 设置 在后台设置首选域名、配置 URL 参数 这两个功能都已下线；改用 301 + canonical + noindex 03
代码压缩 开启 Cloudflare Auto Minify 这个功能已经下线；改在构建阶段压缩 03
查外链 用 Google 的 link: 指令 这个指令早已停用；改用 Ahrefs / Semrush / Moz 和 GSC 的链接报告 05
域名 用完全匹配域名、买过期域名来借权重 用品牌化、好记的域名；"过期域名滥用"已被写进 Google 的政策 03
寄生内容 在高权重平台上用关键词堆砌的帖子、借别人网站发不相关内容 在平台上发自己的原创内容没问题；借权重属于"网站声誉滥用" 04
长文分页 超长文章分成多页，每页单独写描述 一页写完，配目录锚点 04
sitemap lastmod 每次构建都把所有 URL 的日期改成今天 写真实的修改日期，否则会被搜索引擎忽略 03
X 卡片调试 用 Twitter Card Validator 预览 这个工具已经不提供预览；在发帖框里直接看 02
