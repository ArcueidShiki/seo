# 内容与 E-E-A-T

> 一句话：帮用户选出有真实搜索需求的题、写出同领域最好的那一篇，并让它看起来像真正做过这件事的人写的。完整内容见仓库 `handbook/04-content-and-eeat.md`（ArcueidShiki/seo）。

## 何时使用
- 用户问"博客该写什么""这个题值不值得写"，或要一份内容日历
- 用户要你写 / 改一篇 SEO 文章、教程、对比文、问题排查文
- 用户要检查网站或文章的 E-E-A-T（作者、About、日期、第一手素材）
- 用户想用 AI 批量写文章，问会不会被 Google 惩罚、AI 检测分要多少
- 用户有一批排在第 11–30 名的词，想用内链和文章推上首页
- 用户要把文章转发到 Medium / Dev.to / Hashnode / 知乎等平台，或做旧文更新

## 核心原则
1. **SEO 内容只服务三类人**：已经遇到问题的人、正在找工具或方案的人、正在比较产品的人；自测"你自己会不会在搜索框输入这个标题"，不会就放弃。
2. **选题 5 问至少 3 个"是"才写**：有人搜？第一页是内容型页面？能比 Top 3 写得更具体？产品能自然出现？6 个月后还成立？
3. **优先长尾、意图明确的小题**；四类常青内容（How-to、X vs Y、问题排查、场景方案）都要覆盖，并互相内链。
4. **答案先行**：开头 1–3 句直接给答案或结论（≤ 80 词），首段自然出现主关键词；配图放首段之后。
5. **写之前列"超越清单"**：看完 Top 10，写下在深度、数据、工具、时效、案例上哪里更好。
6. **写作规范**：移动端每段约 100 个汉字以内；至少 1 个视觉素材；至少 1 个权威外部引用；关键词写法全文一致。
7. **E-E-A-T 不是单独排名因素，可信是地基**：每篇署名并链接作者页 / About；有 About 和 Contact 页；显示发布和更新日期；每篇支柱文章至少 1 个第一手素材。
8. **YMYL（钱、健康、法律）**要有免责声明、写明风险、不夸大承诺。
9. **5 篇文章法**：挑 GSC / Bing 平均排名约 11–30 的具体长尾词，写 5 篇，文章 2–5 → 文章 1 → 产品页（锚文本 = 长尾词，开头一次 + 结尾一次）。
10. **先首发再转载**：自己站发布 → 当天在 GSC 提交 → 被收录后再转载前约 70% 到高权威平台，文末链回原文，能设 canonical 就指回原文。
11. **AI 只起草**：人写提纲、人加第一手素材、人核对事实；判断标准是内容质量和有没有第一手信息，不是"是不是 AI 写的"。
12. **只在内容真的改了时更新 `dateModified` 和 `<lastmod>`**；只改日期刷新会让日期信号失去可信度。
13. **量变才有质变**：原文观察 10–20 篇几乎没效果，同一垂直领域写到 500–1,000 篇一定有效果；流量向第一名高度集中。

## 操作流程
1. **收集输入**：产品与目标用户、已有关键词或 GSC 查询数据、已发布文章清单、作者身份（可验证的经历、社交账号）、可投入的写作频率、目标语言与平台。
2. **选题**：从关键词表（或先调用 seo-guide-keyword-research）拿候选词，逐个过"选题 5 问"，打分并标注内容类型（四类之一）。
3. **SERP 与超越清单**：查看 Top 10，记录 Top 3 的弱点（堆关键词、泛泛开头、无实操细节、无真实截图），写出超越清单和产品的出现方式。
4. **写 brief / 提纲**：按内容结构模板定 H2 / H3，标出需要用户提供的第一手素材位置，例如 `[截图：…]`、`[真实数据：…]`、`[踩坑经历：…]`。
5. **起草正文**（用户要求时）：遵守写作规范；答案先行；FAQ 3–6 个问句式 H3，每个第一句给结论；结尾 CTA 用描述性锚文本链到产品页。不得编造数据、案例或用户评价，缺的素材留占位符请用户补。
6. **E-E-A-T 检查**：逐项过下方落地清单，缺什么列什么。
7. **内链规划**：用 5 篇文章法排出漏斗和锚文本；同时检查四类内容之间的互链。
8. **分发计划**：选平台、定顺序、设 canonical；提醒用户发布后在页面源码检查 `rel` 实际值。
9. **更新 SOP**：按触发条件表给出本月 / 本季度要更新的文章。
10. **输出**选题表 + 提纲 / 正文 + 检查结果 + 下一步。

## 关键数字与门槛
| 指标 | 门槛/建议值 | 说明 |
|---|---|---|
| 选题 5 问 | ≥ 3 个"是" | 否则不写 |
| 答案先行 | 开头 1–3 句，≤ 80 词 | 对应 `geo-answer-first` |
| 段落长度 | 移动端约 100 个汉字以内（3–4 行） | 总-分-总 |
| 视觉素材 / 外部引用 | 各 ≥ 1 | `links-external-citation` |
| FAQ | 3–6 个问句式 H3 | `geo-faq-blocks` |
| 5 篇文章法目标词 | 平均排名约 11–30 | GSC / Bing 数据 |
| 转载比例 | 前约 70% 内容 + 原文链接 | 原文被收录后再转 |
| 发布节奏 | 起步每周 1–2 篇，或每 2–3 周 1 篇深度文章 | 以能长期保持质量为准 |
| 起步深度文章 | 约 10 篇 | 行业趋势、竞品 / 工具对比、客户案例 |
| 头部通吃（原文估算） | 第 1 名 70%+、第 2 名约 25%、其余约 5% | 做不到第一就缩小范围 |
| 规模效应（原文观察） | 10–20 篇几乎无效；500–1,000 篇一定有效 | 前期曲线很平 |
| 社交内容比例 | 约 80% 有用内容 + 10% 产品 + 10% 个人生活 | 一个账号一个垂直主题 |
| AI 检测分 | 原文 < 40%，仅作参考 | 误判率高，不当目标 |
| 外包改写 | Upwork 约 $200/篇（原文） | AI 起草 → 自改 1 小时 → 写手改写 |

## 模板与示例
**文章结构**
```markdown
# [主关键词] + 具体收获                         ← title 和 H1 都含主关键词
开头 1–3 句直接给答案或结论（≤ 80 词），首段自然出现主关键词
（配图放首段之后）
## 目录（长文才需要）
## 是什么 / 为什么会遇到这个问题
## 怎么做：Step 1 / Step 2 / Step 3              ← <ol>，每步配真实截图
## 对比：方案 A vs B vs C                        ← 表格
## 常见错误与避坑                                ← 第一手经验最值钱
## 常见问题                                      ← 3–6 个问句式 H3，第一句给结论
## 总结 + 下一步                                 ← 再提一次主关键词；CTA 链到产品页
作者署名（链接 /about）· 发布日期 · 更新日期 <time datetime="2026-10-20">
```

**四类常青内容**
| 类型 | 标题模板 | 产品怎么出现 |
|---|---|---|
| How-to | How to [完成任务]（in N steps） | 其中一步的工具 |
| X vs Y | X vs Y：差异、价格、适合谁 | 选项之一，诚实写优缺点 |
| 问题排查 | Why [X] doesn't work / [X] 失败的 5 个原因 | 其中一种修复方式 |
| 场景方案 | [X] for [人群 / 平台] | 实现方式 |

**5 篇文章漏斗**
```text
文章 2 ─┐
文章 3 ─┼─（锚文本 = 长尾词）─▶ 文章 1 ─（锚文本 = 长尾词，dofollow，开头 + 结尾各一次）─▶ 产品页
文章 4 ─┤
文章 5 ─┘
```

**E-E-A-T 落地清单**
```text
[ ] 每篇有作者署名，链接作者页 / About；作者页有可验证身份（社交账号、经历）
[ ] About 和 Contact 页可从页头或页脚进入，返回 200
[ ] 显示发布日期和更新日期（<time datetime>、dateModified）        content-eeat-signals
[ ] 每篇支柱文章 ≥ 1 个第一手素材：原创截图、具体数字、真实限制或失败经历
[ ] YMYL 话题有免责声明、写明风险
[ ] 至少 1 个可被引用的资产：免费工具 / 数据集 / 原创研究 / 模板库 / 参数对照表
[ ] Article.author → Person；首页有 Organization
[ ] GSC 每月跟踪品牌词展示量（权威度代理指标）
```

**内容更新 SOP**
| 触发条件 | 动作 | 频率 |
|---|---|---|
| GSC 出现未回答的查询词 | 补 FAQ / 段落，必要时新开页 | 每月 |
| 展示高、点击率低 | 改写 title 和 description（更具体、带数字、带利益点） | 每月 |
| 排名在 11–30 徘徊 | 加深内容 + 5 篇文章法内链 + 补外链 | 每月 |
| 价格、截图、年份、功能过时 | 更新正文 → 更新 dateModified 和 lastmod | 每季度 |
| 多篇争同一个词 | 合并成一篇，其余 301 | 每季度 |
| 长期 0 展示、内容单薄 | 补充、合并或删除（noindex / 410） | 每半年 |
| 产品上新功能 | 写"把功能翻译成搜索问题"的文章，更新相关内链 | 随版本 |

**分发平台（链接属性为原文标注，会变）**：Substack 大多 follow；Hashnode follow、支持 canonical；Dev.to follow、front matter 可写 `canonical_url`；Blogger follow；Medium nofollow、导入文章自动设 canonical；V2EX nofollow。

## 常见错误与过时做法
- ⚠️ 主题太散；写开发者自己关心的话题（技术架构）而不是用户关心的问题；坚持时间太短。
- ⚠️ 去掉产品后文章反而更通顺 → 转化价值低。
- ⚠️ 只改日期不改内容来"刷新"文章。
- ⚠️ 转载不设 canonical → 转载版可能排在原文前面。
- ⚠️ **2026 判断**：关键词密度 2%–8%、description 关键词约 3 次、超长文分页、刻意加粗关键词都已过时；只有面向百度时 meta keywords 才有一点作用。
- ⚠️ **2026 更新**：Google 官方看内容质量而不看是否 AI 写；真正打击的是"规模化内容滥用"。AI 检测器误判率高，"< 40%"不是目标，为骗检测器洗稿不会让内容变好。
- ⚠️ **2026 更新**：不要一次性批量发几百篇；抖音、小红书会明确压低模板化、AI 腔内容。
- ⚠️ **2026 更新**：中文平台长文打法（知乎、豆瓣、简书 ≥ 3,000 字围绕一个词）仍可用，但"关键词出现 ≥ 20 次"属于堆砌。
- ⚠️ **2026 更新**：付费在别人网站发布与对方主题无关的内容借权重，属于 2024 年政策里的"网站声誉滥用"；发自己的原创内容到高权威平台没问题。
- ⚠️ 用 Surfer SEO 之类工具查术语覆盖可以，但不要为凑分堆词。

## 交付格式
1. **选题表**（按优先级排序）：

| 优先级 | 标题 | 类型 | 主关键词 | 5 问得分 | Top 3 弱点 | 超越点 | 需要的第一手素材 | 内链目标 | 排名可能性 |
|---|---|---|---|---|---|---|---|---|---|

   优先级 P0 / P1 / P2；"排名可能性"用高 / 中 / 低 + 依据（5 问得分、SERP 构成），明确是估计。
2. **提纲或正文**：按结构模板输出，第一手素材位置用占位符标出，不编造数据与案例。
3. **E-E-A-T 检查结果**：逐项 ✅ / ❌ + 修复建议。
4. **内链与分发计划**：5 篇文章漏斗图 + 平台、顺序、canonical 设置。
5. **下一步**：本周可执行的最多 3 个动作 + 下次复盘时间（按更新 SOP 频率）。
