# 变现：模型选择、验证、广告、订阅、支付与联盟

> 一句话：帮用户先定变现模型、用留存和"单次访问收益 vs CPC"验证，再给出广告 / 订阅 / 支付 / 联盟的具体方案。完整内容见仓库 `handbook/12-monetization.md`（ArcueidShiki/seo）。

## 何时使用

- 用户问产品该怎么赚钱：广告、订阅、买断、付费专栏、CPS 怎么选
- 用户要给 SaaS / 工具定价，设计免费层、PRO 权益、试用方式
- 用户要申请 AdSense 或其他广告网络，或估算广告收入 / RPM
- 用户要选支付渠道（Stripe、Paddle、Creem、Lemon Squeezy 等），关心 KYC、MoR、抽成和税
- 用户要开联盟分佣计划、找 KOL 按 CPA / CPS 合作，或自己做 CPS 推广
- 用户问"现在能不能开始投广告 / 请 KOL"

## 核心原则

1. 动手前写下三件事：收入模型、目标用户、价值主张；门槛越低的模型竞争越激烈。
2. 留存 4-2-1：D1 ≥ 40%、D7 ≥ 20%、D30 ≥ 10%；低于及格线先修产品，不加大获客。
3. 一次性需求工具不看留存，看跳出率、平均访问时长和直接访问占比（用户记住网址是"被需要"的最好信号）。
4. 单次访问收益 = 月收入 ÷ 月自然访问量；≥ 核心词平均 CPC 才考虑付费获客或 KOL，否则先优化定价、转化路径和 PRO 价值。
5. 免费层要真的解决问题，核心价值不注册就能看到、能用；PRO 权益要清楚；用终身买断价、用户评价、紧迫感提升转化。
6. 定价流程：先上线简单价格 → 访谈第一个付费用户 → 调套餐、价格锚点、年付折扣 → 定价稳定且结账顺畅后才投放。
7. 广告只用横幅或原生格式；开广告前后各跑一次 PageSpeed 确认 CLS 没变差；审核通过后配置 `/ads.txt`。
8. 用"预计 PV × RPM"对比"预计付费用户 × 客单价"；工具类产品通常订阅 / PRO 收入更高，广告作为免费用户的补充。
9. 支付：先确认自己的主体能通过哪家 KYC 再开发结账页；平台抽成和税费计入定价，算出每单净收入。
10. Cloudflare 后的支付 webhook 子域用灰云（仅 DNS）或放行支付平台 IP，否则会"用户付了钱但没开通"。
11. AI 产品的免费层和买断用户会长期消耗模型调用费：对 `/api`、`/generate`、注册接口设速率限制，买断前先算毛利。
12. 获客预算从第一天列进成本模型（≥ 约 $100/月）；先把一个产品做到有自然收入，再开下一个。

## 操作流程

1. **收集信息**：产品类型与使用频次（高频 SaaS / 一次性工具 / 内容站）、目标市场、用户所在国家与主体类型（个人 / 公司；中国大陆 / Stripe 支持的国家）、月 PV 与自然访问、当前收入、留存数据、核心词 CPC、成本结构（尤其 AI 调用成本）。
2. **选模型**：按"变现模型表"匹配 1–2 个主模型，说明门槛与前提。
3. **验证**：计算留存是否达到 4-2-1（一次性工具改看三指标），计算单次访问收益并与 CPC 比较，给出"可以放大 / 先优化"的判断。
4. **广告 vs 订阅测算**：用 RPM 公式和订阅收入公式并排估算，列出影响 RPM 的因素（国家、领域、每次访问页数、版位密度）。
5. **定价与试用**：划分免费 / PRO 权益，推荐一种试用方式，列价格页要素，给出访谈第一个付费用户的问题清单。
6. **广告申请**（如适用）：过 AdSense 准备清单，推荐备选广告网络并提示侵入式格式风险。
7. **支付渠道**：按用户主体从对比表推荐 1–2 家（是否需要 MoR 代缴税），列出抽成与上线前支付检查。
8. **联盟**：作为广告主设计分佣计划与 KOL 计费方式（每人独立追踪链接）；作为推广者给出 CPS 选品原则。
9. **交付**：按"交付格式"输出，并标注放大时机。

## 关键数字与门槛

| 指标 | 门槛/建议值 | 说明 |
|---|---|---|
| D1 次日留存 | ≥ 40% | 低于则先修产品 |
| D7 七日留存 | ≥ 20% | 同上 |
| D30 三十日留存 | ≥ 10% | 同上 |
| 单次访问收益 | ≥ 核心词平均 CPC | 才考虑付费获客 / KOL |
| 自然流量价值 | 日访问 × 平均 CPC | 例：100 次/天 × $0.50 = $50/天 |
| 获客预算 | ≥ 约 $100/月 | 第一天就列入成本模型 |
| Gumroad 抽成 | 10% | 定价时计入 |
| 一次性工具替代指标 | 跳出率 / 平均访问时长 / 直接访问占比 | 直接访问占比高 = 被需要 |
| 组件库示例 | 免费浏览 + 一次性 $49 解锁全部 | 原文 PRO 示例 |
| 导航站模板 | Mkdirs，1–2 小时可部署 | 广告 + 付费收录模型 |
| 品牌合作起点 | 约 1k–5 万粉 | 小红书等创作者 |
| 私域估算 | 2 万好友 × 1% × ¥200 ≈ ¥4 万 | 代入自己的转化率 |

## 模板与示例

**核心公式**

```
自然流量价值   = 日访问量 × 核心关键词平均 CPC
单次访问收益   = 月收入 ÷ 月自然访问量
RPM           = 广告收入 ÷ 页面浏览量 × 1000
月广告收入     ≈ 月 PV ÷ 1000 × RPM
订阅收入对比   ≈ 预计付费用户 × 客单价
```

**变现模型表**

| 模型 | 适合 | 前提 |
|---|---|---|
| 广告 | 流量大、单次需求的工具站 / 内容站 | 稳定流量、内容合规 |
| 订阅（免费 + PRO） | 高频 SaaS / 工具 | 免费层真有用，PRO 价值清楚 |
| 买断 / LTD | 早期需要现金流和曝光 | 算清长期成本（AI 调用） |
| 付费专栏 / 知识付费 | 有内容输出能力的个人 | 有个人品牌 |
| 导航站：广告 + 付费收录 | 擅长做流量 | 能做 SEO，竞争多 |
| CPS / 联盟 | 有精准受众，暂无产品 | 选品匹配受众 |
| 课程 / 视频广告分成 / 品牌合作 | 已有影响力的创作者 | 平台开通门槛 |

**试用设计**

| 方式 | 优点 | 风险 / 适合 |
|---|---|---|
| 永久免费层 + 付费升级 | 利于 SEO 和口碑 | 免费层成本要可控 |
| 限时试用（不绑卡） | 注册门槛低 | 转化偏低，需引导到核心价值 |
| 限时试用（绑卡） | 转化高 | 注册少，需清晰取消说明 |
| 按额度 / 积分 | AI 产品能控成本 | 额度要够体验核心价值 |

**支付渠道对比**（"个人可用 / 需海外实体"是站在中国大陆开发者角度；在美国、澳大利亚等 Stripe 支持的国家，个人或独资经营者通常可直接开 Stripe）

| 渠道 | 个人可申请 | 需海外实体 | MoR | 备注 |
|---|---|---|---|---|
| Creem | ✅ | — | 以官网为准 | 原文列为个人可用 |
| Paddle | ✅ | — | ✅ | SaaS 常用，审核偏严 |
| PayPal | ✅ | — | ❌ | 覆盖广，有争议与冻结风险 |
| Waffo | ✅ | — | 以官网为准 | 原文列为个人可用 |
| Stripe | ❌（中国大陆） | ✅ | ❌（Stripe Tax 可算税） | 生态最完整 |
| PayPro Global | ❌ | ✅ | ✅ | 软件 / SaaS 分销 |
| Paydify | ❌ | ✅ | 以官网为准 | — |
| Lemon Squeezy | 原文未注明 | 原文未注明 | ✅ | 2024 年被 Stripe 收购，内置联盟 |
| Polar | 原文未注明 | 原文未注明 | ✅ | 面向开发者 / 开源 |

创作者平台：Gumroad（抽 10%）、小报童（付费专栏）、爱发电、Buy Me a Coffee、Substack。

**上线前支付检查**

```
[ ] 主体能通过哪家 KYC 已确认
[ ] 抽成 + 税费计入定价，算出每单净收入
[ ] 真实支付和退款各端到端测一次
[ ] webhook 可达（Cloudflare 灰云或放行 IP）
```

**访谈第一个付费用户**：为什么付钱？对比了哪些替代方案？觉得贵还是便宜？

**AdSense 准备**：原创有实际内容的页面（工具站配说明 / 教程 / FAQ）、页脚可进入 About / Contact / 隐私政策、符合发布商政策、导航清晰无大量死链空页、通过后配 `/ads.txt`、GDPR 地区展示同意弹窗。

## 常见错误与风险

- ⚠️ 审核宽松的广告网络提供弹窗、跳转、全屏插页等侵入式格式：伤体验、拉高跳出率、拖累 CWV，甚至被浏览器安全机制标记。
- ⚠️ 广告版位过多：伤害体验和排名，不一定带来更多收入。
- ⚠️ 留存或付费率未达标就请 KOL / 投广告。
- ⚠️ 不确认 KYC 就开发结账页；定价时漏算平台抽成和税费。
- ⚠️ webhook 被 Cloudflare 拦截，导致付款后未开通。
- ⚠️ AI 产品做买断（AppSumo 等）不先算模型调用的长期毛利；免费层没有限流防刷。
- ⚠️ ShareASale 已并入 Awin（据公开消息 2025 年完成迁移），新开联盟计划先确认入口。
- ⚠️ 推广没用过、和受众不匹配的产品，或不按规定披露推广关系。
- ⚠️ "蹭知名品牌名做公众号 + 漫画小说 CPS"有商标风险，不要模仿。
- ⚠️ 渠道政策和 MoR 状态会变化，"以官网为准"的项必须复核。

## 交付格式

- 开头一句结论：推荐的主模型 + 当前是否可以放大（附验证数据）。
- 验证表：`指标 | 当前值 | 门槛 | 是否达标 | 动作`。
- 收入测算表：广告 vs 订阅两种情景并排，写清假设（PV、RPM、付费率、客单价）。
- 定价 / 支付 / 联盟各给一张 `选项 | 推荐度(P0/P1/P2) | 理由 | 风险` 表。
- 对"付费转化能否提升 / 渠道能否过审"用高 / 中 / 低可能性 + 依据表述，不编造精确概率；所有用户未提供的数字明确标为假设。
